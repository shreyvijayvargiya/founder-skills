# Content Refresh And Repurpose

## Mission

Combine **content decay recovery** with **distribution** — update what is declining, then multiply each asset across channels.

Use when the user asks:

- Refresh old blog posts and repurpose them
- Turn my blog into social posts
- Update declining content and get X / LinkedIn / newsletter from it
- Content ops for an existing blog

Builds on ideas from **content-decay-recovery** but always includes repurpose deliverables.

---

# Input

## Required

- Website URL

## Optional

- Blog URL or sitemap section
- Search Console / analytics hints (user-provided)
- List of priority posts
- Brand voice
- Newsletter name and typical length
- Social handles (tone only — no posting automation)
- Customer voice phrases for hooks

Do not invent traffic numbers.

---

# Workflow

## 1. Select Candidates

Find pages to work on:

- Declining or stale posts (dates, outdated examples, weak SERP fit)
- High-potential posts worth updating (strong topic, thin refresh needed)
- Evergreen posts due for a light factual update

If no analytics provided, use public dates, SERP freshness signals, and obvious staleness — label confidence.

Cap focus at **3 posts** unless user asked for more (founder-friendly scope).

---

## 2. Refresh Plan Per Post

For each selected post:

- Decay or staleness signal
- Sections to update (stats, screenshots, product changes, new subtopics)
- Intent check (does SERP format still match?)
- Internal links to add (topics only — full link map optional)
- Publish approach: silent update vs "updated for 2026" note

Do not recommend rewriting the entire library.

---

## 3. Repurpose Pack Per Post

For each refreshed (or current) post, produce:

### X thread

- 5–8 tweets: hook, key insights, one concrete takeaway, CTA to post
- First tweet must stand alone

### LinkedIn post

- Native post: one insight expanded, personal/founder angle optional, link at end
- ~150–250 words

### Newsletter blurb

- Subject line option
- 2–3 paragraph summary with "read more" CTA
- One bullet "why read this now"

All three must reflect the **same core idea** without identical copy-paste spam.

---

## 4. Calendar Hint

Suggest a simple rollout:

- Day 0: publish refresh
- Day 0–1: X thread
- Day 1–2: LinkedIn
- Day 3–7: newsletter slot

# Quality Rules

- No fabricated analytics.
- Repurpose from real post content — if post is thin, say so before inflating thread length.
- Respect platform norms (LinkedIn native tone, X concise).
- Founder-focused marketing content — not developer docs unless blog is technical.
- Skip programmatic SEO and net-new page factories in this skill.
